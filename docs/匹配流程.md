# 匹配流程

## Configuration and safety

`configs/matching_specs.json` is the single source of truth for:

- enabled years;
- ICIO/AMNE path templates;
- the country-pair score source;
- tariff and Gravity paths;
- output root;
- ISO aliases and ROW/domestic policy;
- selected and candidate controls.

All configured paths are project-relative. `--dry-run` resolves and validates
inputs but writes nothing. Without `--force`, an existing output causes an
error before the pipeline reads Gravity or starts output construction.

## `match_y_x`

| Step | Input | Output / responsibility |
|---:|---|---|
| 01 | config, ICIO/AMNE headers/data, pair scores | source existence, fields, years, unique keys, planned paths |
| 02 | `icio{year}.dta` or `amne{year}.dta` | standardized Y with original/match ISO fields and ROW/domestic flags |
| 03 | pair-year score source | unique directed pair-year `raw_trade_score` and `raw_mp_score` only |
| 04 | ICIO Y + X | trade Y-X with `raw_trade_score` |
| 05 | AMNE Y + X | MP Y-X with `raw_mp_score` |
| 06 | trade/MP Y-X | CSV/DTA, diagnostics, manifest |

The Y-X outputs prohibit tariff, agreement dummy, political distance, Gravity
fields, `entry_*`, and main-sample flags.

Run:

```bash
python run_pipeline.py match-y-x --years 2019 --dry-run
python run_pipeline.py match-y-x --years 2019
```

Outputs:

```text
result/model_inputs/match_y_x/{year}/
  trade_y_x_{year}.csv
  trade_y_x_{year}.dta
  mp_y_x_{year}.csv
  mp_y_x_{year}.dta
  matching_diagnostics.json
  build_manifest.json
```

## `match_y_x_cons`

| Step | Input | Output / responsibility |
|---:|---|---|
| 01 | pair-year source | agreement dummy and political distance only |
| 02 | `tariff_{year}.csv` | numeric directional keys, tariff, match flag |
| 03 | Gravity CSV | chunk-filtered directed pair-year candidate controls |
| 04 | trade Y-X + tariff + pair + Gravity | row-preserving trade candidate data |
| 05 | MP Y-X + pair controls | MP controls; no tariff or Gravity |
| 06 | matched datasets | diagnostic completeness/availability flags |
| 07 | configured datasets | CSV/DTA, diagnostics, dictionary, manifest, README |

Gravity reads only:

```text
year, iso3_o, iso3_d, country_exists_o, country_exists_d,
gatt_o, gatt_d, wto_o, wto_d, eu_o, eu_d,
fta_wto, fta_wto_raw, rta_coverage, rta_type,
entry_cost_o, entry_cost_d, entry_proc_o, entry_proc_d,
entry_time_o, entry_time_d, entry_tp_o, entry_tp_d,
gmt_offset_2020_o, gmt_offset_2020_d,
comlang_off, comlang_ethno, comrelig,
legal_old_o, legal_old_d, legal_new_o, legal_new_d,
comleg_pretrans, comleg_posttrans, transition_legalchange,
comcol, col45, heg_o, heg_d,
col_dep_ever, col_dep, col_dep_end_year, col_dep_end_conflict,
empire, sibling_ever, sibling, sever_year, sib_conflict,
scaled_sci_2021, diplo_disagreement
```

It filters the requested year first, requires both country-existence flags,
keeps only target economies, and validates a unique directed square. It never
averages origin and destination fields and never fills missing values.

Configured derived candidates are:

```text
both_gatt = gatt_o * gatt_d
both_wto = wto_o * wto_d
both_eu = eu_o * eu_d
cultural_distance_religion = 1 - comrelig
```

All direct and derived Gravity fields above are matched candidates only. They
are not automatically selected. In particular, `entry_*` measures business
start-up conditions rather than customs clearance, logistics performance, or
border efficiency. `rta_coverage`, `rta_type`, `legal_old_o/d`,
`legal_new_o/d`, and `empire` retain the numeric category codes distributed in
the CEPII CSV.

Run:

```bash
python run_pipeline.py match-y-x-cons --years 2019 --control-spec trade_candidate_pool_v1
python run_pipeline.py match-y-x-cons --years 2019 --control-spec mp_controls_v1
```

Outputs:

```text
result/model_inputs/match_y_x_cons/{control_spec}/{year}/
  trade_y_x_cons_{year}.csv/.dta  # when the spec includes trade
  mp_y_x_cons_{year}.csv/.dta     # when the spec includes MP
  matching_diagnostics_{year}.csv
  variable_dictionary_{year}.csv
  build_manifest.json
  README.md
```

## Diagnostic sample flags

Trade:

- `sample_trade_y_x`: `value` and `raw_trade_score` are present.
- `sample_trade_base_controls`: adds tariff, agreement dummy, and political
  distance completeness.
- `available_entry_cost`, `available_entry_proc`, `available_entry_time`,
  `available_entry_tp`, `available_comlang`, and `available_comrelig` diagnose
  candidate availability one family at a time.

MP:

- `sample_mp_y_x`: `value` and `raw_mp_score` are present.
- `sample_mp_controls`: adds agreement dummy and political distance
  completeness.

No composite main-sample flag is created.

## Legacy validation

`legacy_2019_v1` is only a refactor regression test:

```bash
python run_pipeline.py match-y-x-cons --years 2019 --control-spec legacy_2019_v1
```

It compares all overlapping fields row by row against
`result/regression_2019` while writing only to the new output tree. The old
directory is never overwritten. Legacy-selected fields do not define the new
research specification.
