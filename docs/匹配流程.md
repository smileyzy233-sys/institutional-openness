# 匹配流程

## Configuration and safety

`configs/matching_specs.json` is the single source of truth for:

- enabled years;
- ICIO/AMNE path templates;
- the country-pair score source;
- tariff and Gravity paths;
- output root;
- ISO aliases and ROW/domestic policy;
- selected and candidate controls.

All configured paths are project-relative. `--dry-run` resolves and validates
inputs but writes nothing. Without `--force`, an existing output causes an
error before the pipeline reads Gravity or starts output construction.

The default sample policy is `drop_row: true, keep_domestic: false`.
Step `match_y_x_02_prepare_y` applies one union filter before X matching.
Comparisons trim whitespace and ignore case, leave original ISO fields unchanged,
and classify domestic pairs only when both endpoints are nonempty/nonmissing.
Set the existing `keep_domestic` switch explicitly to `true` to retain domestic
pairs in DTA; `drop_row` remains independent. Missing switches use the defaults.
Audit records include both category counts, their overlap, actual total deletions,
and before/after row counts. Configured `*_rows_excluding_row` acceptance values
validate the ROW-free source baseline independently of the domestic switch;
the final expected row count comes from the actual union filter and is checked
again after the Y-X join.

Before control matching, including dry-run, the Y-X manifest must declare the
same row policy and its CSV hash must match. A conflict requires rebuilding Y-X
in a new version root; `--force` does not bypass compatibility checks. Control
joins never filter their base. New control manifests reference and hash the
upstream Y-X manifest, which holds the original filtering audit.

**Existing `outputs/matched_data` has not been rebuilt and still uses
`keep_domestic: true`.** Historical logs/manifests are unchanged. See
[sample policy change and rebuild instructions](sample_policy_change_20260915.md).

The upstream measurement rule is separate from control-variable missingness:
blank DTA provision-coverage cells are counted as `0` when the coverage matrix
and the indicators are calculated, while the coding workbook may retain the
original blank. `NR` continues to follow the existing coding rules. This rule
does not apply to tariffs, political distance, Gravity fields, or other
controls; missing controls remain missing and are never filled with `0`.
The fractional X path continues to use the existing LLM classifications and
valid Trade/MP weights; this documentation update does not rerun classification
or regenerate weights.
The confirmed measurement decisions and compatibility audit are recorded in
`docs/measurement_decisions_20260915.md` and
`manifests/measurement_compatibility_20260915.json`.

## `match_y_x`

| Step | Input | Output / responsibility |
|---:|---|---|
| 01 | config, ICIO/AMNE headers/data, pair scores | source existence, fields, years, unique keys, planned paths |
| 02 | `icio{year}.dta` or `amne{year}.dta` | standardized Y with original/match ISO fields and ROW/domestic flags |
| 03 | pair-year score source | unique directed pair-year `raw_trade_score` and `raw_mp_score` only |
| 04 | ICIO Y + X | trade Y-X with `raw_trade_score` |
| 05 | AMNE Y + X | MP Y-X with `raw_mp_score` |
| 06 | trade/MP Y-X | CSV/DTA, diagnostics, manifest |

The 2000 ICIO/AMNE source files currently contain only `iso_o`, `iso_d`,
`sector_amne`, and `value`. The matching code supplements
`country_o`, `country_d`, `iso_o1`, and `iso_d1` from
`Explained_variable/iso_o.dta`. The 2019 ICIO/AMNE files already contain those
identity fields. This fallback only supplies identity fields and does not
change Y.

The Y-X outputs prohibit tariff, agreement dummy, political distance, Gravity
fields, `entry_*`, and main-sample flags.

Run:

```bash
python run_pipeline.py match-y-x --years 2019 --dry-run
python run_pipeline.py match-y-x --years 2019
```

Outputs:

```text
outputs/matched_data/match_y_x/{year}/
  trade_y_x_{year}.csv
  trade_y_x_{year}.dta
  mp_y_x_{year}.csv
  mp_y_x_{year}.dta
  matching_diagnostics.json
  build_manifest.json
```

For the current fractional X path, the existing DTA coding, LLM
classifications, and valid Trade/MP weights feed
`data/processed/agreement_level_indices.csv`,
`data/processed/country_pair_year_indices.csv`, and then
`data/processed/trade_dummy_icio_2000_2023.csv`. `match_y_x` reads that final
pair-year file directly and does not recalculate scores.

## `match_y_x_cons`

| Step | Input | Output / responsibility |
|---:|---|---|
| 01 | pair-year source | agreement dummy and political distance only |
| 02 | year-specific tariff source (`tariff2000.dta` or `tariff_2019.csv`) | numeric directional keys, tariff, match flag |
| 03 | Gravity CSV | chunk-filtered directed pair-year candidate controls |
| 04 | trade Y-X + tariff + pair + Gravity | row-preserving trade candidate data |
| 05 | MP Y-X + pair controls | MP controls; no tariff or Gravity |
| 06 | matched datasets | diagnostic completeness/availability flags |
| 07 | configured datasets | CSV/DTA, diagnostics, dictionary, manifest, README |

Gravity reads only:

```text
year, iso3_o, iso3_d, country_exists_o, country_exists_d,
gatt_o, gatt_d, wto_o, wto_d, eu_o, eu_d,
fta_wto, fta_wto_raw, rta_coverage, rta_type,
entry_cost_o, entry_cost_d, entry_proc_o, entry_proc_d,
entry_time_o, entry_time_d, entry_tp_o, entry_tp_d,
gmt_offset_2020_o, gmt_offset_2020_d,
comlang_off, comlang_ethno, comrelig,
legal_old_o, legal_old_d, legal_new_o, legal_new_d,
comleg_pretrans, comleg_posttrans, transition_legalchange,
comcol, col45, heg_o, heg_d,
col_dep_ever, col_dep, col_dep_end_year, col_dep_end_conflict,
empire, sibling_ever, sibling, sever_year, sib_conflict,
scaled_sci_2021, diplo_disagreement
```

It filters the requested year first, requires both country-existence flags,
keeps only target economies, and validates a unique directed square. It never
averages origin and destination fields and never fills missing values.

Configured derived candidates are:

```text
both_gatt = gatt_o * gatt_d
both_wto = wto_o * wto_d
both_eu = eu_o * eu_d
cultural_distance_religion = 1 - comrelig
```

All direct and derived Gravity fields above are matched candidates only. They
are not automatically selected. In particular, `entry_*` measures business
start-up conditions rather than customs clearance, logistics performance, or
border efficiency. `rta_coverage`, `rta_type`, `legal_old_o/d`,
`legal_new_o/d`, and `empire` retain the numeric category codes distributed in
the CEPII CSV.

Run:

```bash
python run_pipeline.py match-y-x-cons --years 2019 --control-spec trade_candidate_pool_v1
python run_pipeline.py match-y-x-cons --years 2019 --control-spec mp_controls_v1
```

Outputs:

```text
outputs/matched_data/match_y_x_cons/{control_spec}/{year}/
  trade_y_x_cons_{year}.csv/.dta  # when the spec includes trade
  mp_y_x_cons_{year}.csv/.dta     # when the spec includes MP
  matching_diagnostics_{year}.csv
  variable_dictionary_{year}.csv
  build_manifest.json
  README.md
```

The fractional matched data and the configured default output root are both
`outputs/matched_data/`. The previous version directory was relocated without
changing file contents. Historical paths are resolved through
`configs/historical_path_mappings.json`; existing manifests are unchanged.

The matching layer defaults to excluding `ROW` and domestic pairs. With explicit
`keep_domestic: true`, DTA can retain domestic pairs; downstream Stata checks and
removes both categories if present, including in old input snapshots. Stata
uses Trade sectors 1–19 and MP sectors 1–20. Trade sector
20 may therefore remain in the matched Trade file with a missing tariff; it is
removed only by the downstream Trade sample restriction, and this is not a
matching-key failure.

The 2026-09-14 audit accepted a small 2019 Trade CSV→DTA storage-precision
difference. The maximum relative difference at the matching layer was
`5.945716743e-8`; in the downstream Stata sample the maximum absolute
difference was `0.0034375`, with zero/positive classification unchanged. The
files are not described as strictly bitwise identical, the difference is not
being repaired, and the audit did not test its effect on new regression
coefficients.

## Diagnostic sample flags

Trade:

- `sample_trade_y_x`: `value` and `raw_trade_score` are present.
- `sample_trade_base_controls`: adds tariff, agreement dummy, and political
  distance completeness.
- `available_entry_cost`, `available_entry_proc`, `available_entry_time`,
  `available_entry_tp`, `available_comlang`, and `available_comrelig` diagnose
  candidate availability one family at a time.

MP:

- `sample_mp_y_x`: `value` and `raw_mp_score` are present.
- `sample_mp_controls`: adds agreement dummy and political distance
  completeness.

No composite main-sample flag is created.

## Legacy validation

`legacy_2019_v1` is only a refactor regression test:

```bash
python run_pipeline.py match-y-x-cons --years 2019 --control-spec legacy_2019_v1
```

It compares all overlapping fields row by row against
the archived baseline formerly at `result/regression_2019`, resolved by
`src/archive_paths.py`, while writing only to the new output tree. The archived
baseline is never overwritten. Legacy-selected fields do not define the new
research specification.
